# 「智阅 SmartRead」语义层阅读提示词设计文档

## 1. 核心理念：从“阅读器”到“认知增强系统”

根据产品愿景，SmartRead 的核心壁垒不在于简单的“AI 总结”，而在于**「语义层阅读」**。这意味着 AI 需要像一个顶级的学术伴读一样，真正理解文本的深层结构：

*   **谁在说话？**（作者 vs 引用对象）
*   **谁在批判谁？**（立场与对抗）
*   **作者的真实观点是什么？**（剥离反讽、引用和背景后的核心主张）
*   **概念之间的逻辑关系是什么？**（推导、并列、对立）

为了实现这一目标，我们设计了专门的 `SEMANTIC_ANALYSIS_PROMPT`，用于驱动阅读器正文区的“智能下划线系统”和右侧的“AI 解读区”。

## 2. 提示词结构设计

提示词分为 `System Prompt` 和 `User Prompt` 两部分，并要求 AI 严格输出 JSON 格式，以便前端进行结构化渲染。

### 2.1 System Prompt (系统设定与任务定义)

**角色设定：**
> “你是一个顶级的学术阅读助手和认知增强引擎。你的核心能力是进行「语义层阅读」。”

**任务目标：**
分析文本片段，提取深层逻辑、立场、关系和结构，并输出结构化 JSON。

**核心提取维度 (对应 UI 功能)：**

1.  **`coreIdea` (核心论点)**
    *   **对应 UI：** 右侧面板的“本段核心观点”。
    *   **要求：** 用一两句话总结作者的真实核心观点，穿透表象。
2.  **`semanticMarkers` (语义标记)**
    *   **对应 UI：** 正文阅读区的“彩色线”和“AI 标签”。
    *   **分类体系：**
        *   `critical` (红线)：批判观点（反驳、批评、质疑）。
        *   `quote` (紫线)：引用（他人话语、历史文献）。
        *   `argument` (黄线)：核心论点（作者自己的核心主张）。
        *   `background` (蓝线)：重要背景（历史、社会、理论背景）。
        *   `definition` (绿线)：定义/结论（明确界定、最终结论）。
    *   **要求：** 提取原文句子，并给出简短的标记理由。
3.  **`keyConcepts` (关键概念)**
    *   **对应 UI：** 右侧面板的“关键概念”标签云。
    *   **要求：** 提取 3-5 个最重要的概念。
4.  **`relations` (人物/概念关系)**
    *   **对应 UI：** 右侧面板的“人物关系图” / 全局“思维导图”。
    *   **要求：** 识别主体 A、主体 B 以及它们之间的动态关系（如：对抗、支持、引用）。
5.  **`extendedThoughts` (延伸思考)**
    *   **对应 UI：** 底部 AI 伴读区的“延伸思考”建议。
    *   **要求：** 提出有深度的启发性问题或历史/现实关联。

### 2.2 User Prompt (上下文注入)

为了让 AI 更好地理解局部文本，必须注入全局上下文：

```text
【书籍上下文信息】
书名：《{book_title}》
当前章节：{chapter_title}

【待分析文本】
{text_content}
```

## 3. 预期 JSON 输出示例

```json
{
  "coreIdea": "作者认为，资本主义的生产过程本质上是剩余价值的榨取过程，而非简单的等价交换。",
  "semanticMarkers": [
    {
      "text": "资产阶级经济学家总是试图将雇佣劳动描绘成一种公平的契约关系。",
      "type": "critical",
      "explanation": "作者在指出并准备反驳资产阶级经济学家的观点。"
    },
    {
      "text": "然而，资本的实质并不在于积累的劳动替活劳动充当进行新生产的手段。",
      "type": "argument",
      "explanation": "引出作者关于资本实质的核心主张。"
    },
    {
      "text": "它的实质在于活劳动替积累的劳动充当保存并增加其交换价值的手段。",
      "type": "definition",
      "explanation": "对资本实质的明确界定。"
    }
  ],
  "keyConcepts": ["剩余价值", "雇佣劳动", "资本实质", "等价交换"],
  "relations": [
    {
      "source": "马克思 (作者)",
      "target": "资产阶级经济学家",
      "relation": "批判"
    },
    {
      "source": "活劳动",
      "target": "积累的劳动",
      "relation": "增值手段"
    }
  ],
  "extendedThoughts": [
    "在现代零工经济（如外卖骑手）中，这种'剩余价值的榨取'形式发生了怎样的隐蔽变化？",
    "如果劳动不再是创造价值的唯一源泉（如 AI 时代），这一理论是否需要修正？"
  ]
}
```

## 4. 前端渲染逻辑映射

当后端 LLM 返回上述 JSON 后，前端将进行如下渲染：

1.  **正文高亮：** 遍历 `semanticMarkers`，在正文中查找对应的 `text`，根据 `type` 渲染不同颜色的下划线（红、紫、黄、蓝、绿），并在旁边显示 `explanation` 作为边注或 Tooltip。
2.  **右侧面板更新：**
    *   将 `coreIdea` 填入“本段核心观点”卡片。
    *   将 `keyConcepts` 渲染为彩色标签。
    *   将 `relations` 转化为可视化节点图（如使用 React Flow 或 ECharts）。
3.  **底部伴读更新：** 将 `extendedThoughts` 作为推荐的 Prompt 按钮显示在底部输入框上方。

## 5. 下一步开发计划

1.  **后端 API 集成：** 在 `main.py` 中新增 `/api/book/{book_id}/analyze_semantic` 接口，调用 `LLMService` 并使用此 Prompt。
2.  **前端 UI 实现：**
    *   实现正文区的多色下划线渲染组件。
    *   实现右侧面板的结构化数据展示组件（特别是关系图）。
3.  **性能优化：** 考虑到语义分析较慢，前端需要实现骨架屏（Skeleton）或流式加载（Streaming JSON）体验。
